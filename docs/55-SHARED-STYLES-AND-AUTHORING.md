# Универсальные стили и добавление статей

## Решение

Новая статья — новые типизированные данные, а не новая таблица стилей.
`FilmArticle` / `ArticleBlock` в `src/lib/film-package.ts` остаются единственным
контрактом статьи. `ArticleView` рендерит все фильмы одинаковыми семантическими
блоками. Производственное досье остаётся отдельным материалом и рендерером.
Ни фильм, ни редакторский текст не выбирают CSS-классы, цвета или inline-style.
Публикационные ограничения, preview и noindex не меняются.

## Владельцы файлов

`src/styles/film-article.css` — только ordered imports:

| Файл в `src/styles/article/` | Ответственность |
|---|---|
| `body.css` | Заголовок, byline, оглавление, разделы, типизированные блоки, таблицы |
| `entry.css` | Ссылка-вход в статью с карточки фильма |
| `production.css` | Производственное досье, факты, история, группы источников |
| `reading.css` | Типографическая доводка, motion fallback, печать, breadcrumbs |

`src/styles/homepage.css` — только ordered imports из `src/styles/home/`:
`hero`, `analysis`, `evidence`, `craft`, `discovery`, `responsive`.
Остальные import-only поверхности:

| Entry | Владельцы |
|---|---|
| `film-modules.css` → `modules/` | analysis, responsive, evidence |
| `film-verdict.css` → `verdict/` | composition, motion, responsive, accessibility |
| `homepage-optics.css` → `optics/` | frame, lenses, interactions, ambient, entrance, accessibility |

`src/app/globals.css` — import-only вход общего каркаса. Владельцы в
`src/styles/shell/`: base (единственный исходный @layer base), header (навигация
и skip-link), shared (общая секционная разметка и CTA), footer, catalog, responsive.
Правила и порядок не изменены; базовый слой не смешивается с unlayered-компонентами.

Каждый файл решает одну группу задач; CSS-импорты сохраняют исходный порядок.
Accessibility-файлы идут после соответствующих эффектов, а не рядом с данными фильма.

Порядок правил сохранён. Сплит сам по себе не вводит cascade layers: перенос
unlayered-правил в layers меняет приоритет относительно CSS Modules и utilities.
Это отдельная миграция с собственной проверкой, а не безопасное переименование.

Общие основы: `tokens.css`, `primitives.css`, `platform.css`, `tilt.css`,
`experience.css`. Не создаём вторую палитру `--color-*` рядом с имеющимися
`--surface-*` / `--ink-*` / `--accent-*`. Legacy-алиасы пока совместимы;
мигрируем только затронутые компоненты с проверкой контраста.

## Как добавить статью без CSS

1. Создать модуль фильма в `src/data/films/`, подключить через существующий registry.
2. Заполнить ArticleBlock: paragraph, aside, illustration, subhead, pullquote,
   timeline, measurement, measurement-table, corrections. Все эти блоки уже оформлены.
3. Иллюстрация выбирает только семантический `layout: wide | inset` и assetId из
   существующего реестра. Нельзя передавать CSS-класс или произвольный цвет.
4. Прогнать domain validation, тесты и аудиты; проверить spoiler projection.
5. Проверить рендер на 1440 и 390, клавиатуру, reduced motion и печать.

Если реально нужен новый тип блока: сначала общий тип и validator, затем один
переиспользуемый renderer и файл ответственного компонента, тесты и browser evidence.
Не делаем исключения по slug, nth-child или названию фильма. Одноразовый спецэффект
не является достаточным основанием для нового блока.

## Проверки

- `npm run audit:styles`: импортный граф без циклов, entry-файлы только компонуют,
  файлы home/article/modules/verdict/optics/shell не растут сверх 450 строк, не знают film identity и не вводят
  `!important` (три существовавших reduced-motion override в verdict сохранены);
  данные фильма не импортируют CSS и не выбирают className/cssText/style.
- Контракт проверяется не только положительным прогоном: 26 тестов создают временные
  данные новой статьи, циклы/пропавшие импорты, нарушения размера и границ стилей.
  Испорченные варианты должны быть отвергнуты; нормальная новая статья проходит.
- `scripts/lib/style-sources.mjs`: аудиты читают поверхность вместе с локальными
  импортами, а не ошибочно считают import-only файл пустой статьёй.
- `CHROME_BIN=… BASE_URL=… npm run audit:style-parity`: 14 маршрутов × 2 ширины,
  computed styles и геометрия элементов сравниваются с до-рефакторинговой базой.
  Это **проверка статического каскада**, не замена скриншотам/axe/motion-проверкам.
  Проба намеренно стабилизирует движение; по ней нельзя заявлять корректность tilt.
- `--write` у fingerprint дважды снимает текущий build и отказывается писать
  невоспроизводимую базу. Обновлять baseline можно только после разбора отличий.
  Сжатый JSON раскрывается обычным gzip; детали сравнения доступны через `--diff`.
  Автоматические имена CSS Modules — только диагностическая подсказка, не визуальная
  идентичность. После Next 16.4.3 сохранены исходные элементы baseline: поменялись
  имена классов, но не измеренные свойства и координаты.

## Следующие отдельные волны

Shell разделён; legacy-var() в исходном CSS больше не используются.
Мост совместимости в tokens.css пока сохранён, но новые использования и переопределения
алиасов запрещены. Контракт автоматически обнаруживает все CSS-файлы под src, включая
новые CSS Modules: не нужно дописывать список при добавлении компонента.

Следующие отдельные задачи — семантические примитивы для новых UI-возможностей,
типографическая согласованность и браузерные проверки состояния/контента. Сам файловый
сплит не доказывает премиальность. Рост контента не должен вызывать рост стилей;
рост UI-возможностей может потребовать нового переиспользуемого компонента.

## Runtime и безопасность (волна 2)

Локальные проверки переведены на Node 24.22.2 без отключения engine-strict.
Контракт engines остаётся 24.x, как и Node в CI. Переход на следующий major без
потребности не нужен: поддерживаемая линия и совместимость важнее номера.
Next.js и eslint-config-next обновлены синхронно 16.3.4 → 16.4.3.
Обновлены совместимые транзитивные sharp/libvips, brace-expansion, source-map-js,
zod через lockfile; новых прямых зависимостей и install-script разрешений нет.
`npm audit` до: 1 critical + 4 high; после: 0. Это снимок npm advisory database,
а не обещание отсутствия всех возможных уязвимостей.

## Семантические токены (волна 3)

Переведены только modules/ и verdict/: 104 var()-ссылки на legacy-алиасы заменены
их существующими семантическими владельцами. Значения палитры, шкалы и размеры
не менялись; aliases в tokens.css сохраняются для немигрированных компонентов.
Не делаем массовую замену всего src: каждую следующую поверхность проверяем отдельно.

Контракт style-tokens проверяет, что alias определён ровно один раз в :root,
ссылается на ожидаемый существующий canonical token, а migrated-владельцы не
возвращаются к legacy-var(). Это не второй набор токенов: словарь фиксирует мост
совместимости, значения принадлежат tokens.css. Контрастные проверки читают ту же
каноническую палитру.

Compatibility-аудит теперь использует уже имеющийся PostCSS: prefixed twin должен
быть в том же declaration block и с тем же значением, до или после стандартного
свойства. Комментарий или соседний селектор не считаются fallback. Расширенный охват
обнаружил отсутствующее -webkit-backdrop-filter: none в forced-colors лаборатории
six-lenses; override исправлен без изменения обычного режима.

Отпечаток расширен до 16 комбинаций маршрута/ширины: к исходным 12 добавлены
FULL-проекции двух пакетов (статья Film 001 и исследовательский черновик Film 002), снятые перед миграцией токенов. Эти четыре комбинации
явно используют reduced-motion (JS-цикл ядра вердикта не является статической CSS
геометрией). Исходные 12 элементов базы не пересняты. Проба теперь прекращает работу,
если CSS/шрифты не стали готовы или раскладка не стабилизировалась; неготовая страница
не может стать базовой линией. Не пересобирать .next под работающим измеряемым сервером:
старый процесс может запрашивать уже удалённые хешированные CSS-ассеты.

## Готовность материала и уровень спойлеров (волна 4)

FULL означает только раскрытие всех спойлерных модулей в preview-проекции.
Это не редакционный статус и не готовность статьи. У «Шоу Трумана» есть FilmArticle
и LOCKED-издание, но публикационный статус остаётся draft/preview-only. У «Форсажа»
нет FilmArticle: это SECONDARY_SOURCES / TARGET_ONLY, не готовая вторая статья.
Досье о производстве Film 001 — отдельный материал, не статья о втором фильме.

Индекс теперь получает статус от общей функции filmIndexStatusLabel: статья в
предпросмотре, исследовательский черновик без статьи, обычный черновик без статьи,
фикстура или опубликованный материал. Эти подписи не меняют доступность маршрутов.
Фильтры preview/public и noindex сохраняются. Изменения текста индекса — намеренные;
обновляются только два соответствующих снимка, не вся визуальная база.

Методология и verdict-core переведены на канонические var()-имена без изменения
значений. Home/optics уже были каноническими; теперь контракт защищает все разделённые
владельцы, методологию и этот CSS Module. Оставшаяся миграция: platform bridge и
лабораторные CSS Modules — отдельные проверяемые участки.

Скриншот индекса выявил внутреннее перекрытие без document overflow: min-height
обложки 58px и preferred aspect-ratio давали ширину ~139px внутри 96px колонки.
Индексная обложка теперь явно ограничена inline-size:100% и min-inline-size:0.
Browser audit проверяет пересечение обложки с названием/статусом на desktop,
mobile и zoom-200; отсутствие scrollbar не считается доказательством читаемости.

## Платформенный мост и лаборатории (волна 5)

Поэтапно заменены оставшиеся 205 legacy-var() ссылок: 196 в лабораторных CSS Modules
и 9 в platform bridge. Величины токенов и раскладка не менялись. Новых зависимостей,
!important и публикационных изменений нет. R&D-страницы остаются noindex и не являются
новыми статьями.

Для шрифтов прямое объявление @theme --font-body:var(--font-body) было бы циклом.
Существующие классы font-body/font-display сохранены как явные @utility с каноническими
font-family var(). Тест запускает настоящий Tailwind/PostCSS и проверяет CSS-вывод
шрифтовых и цветовых utilities — не только наличие строк в исходнике.

Контракт охватывает все 53 текущих CSS-файла под src и обнаруживает новые автоматически.
Alias definitions допускаются только в проверяемом tokens.css, legacy-var() — нигде.
Пути нормализованы для одинакового охвата CSS Modules на Windows и Linux.

Базовая выборка расширена до 28 комбинаций: исходные 16 снимков сохранены, добавлены
12 лабораторных снимков на 1440/390, записанные до миграции и дважды воспроизведённые.
Лабораторный fingerprint явно использует reduced-motion и проверяет статический каскад;
живое управление проверяется отдельным browser audit. Для six-lenses добавлены mobile,
zoom-200 и клавиатурный End: последняя линза должна стать выбранной, получить фокус,
появиться в видимой области горизонтальной панели и подписать tabpanel.


## Общие таблицы и врезки (волна 6)

Оба табличных ArticleBlock используют серверный ArticleTable: одна внешняя подпись
именует нативную таблицу и фокусируемую область прокрутки. Заголовки col/row остаются
в типизированном renderer; клиентский JS, зависимости и film-specific CSS не добавлены.
Табличные правила принадлежат article/tables.css (54 CSS-владельца под src).
Подпись не прокручивается вместе с данными; длинные токены переносятся. На бумаге
viewport не обрезается, числовые ячейки получают обычный перенос вместо nowrap.
Врезка — именованная inline note, не вложенный complementary landmark; её отдельный
редакционный регистр сохранён. Аудит мёртвых классов читает все компоненты film-article.

SSR-тест реально рендерит TSX через react-jsx и проверяет связь имён, escaping и scope.
Browser audit разделяет настоящую статью и синтетический длинный ввод: 1440/390,
zoom-200, reduced-motion, видимый фокус, нативный ArrowRight, отсутствие внешнего
overflow и печать. В fingerprint обновлены только два вида статьи; остальные 26
исторических записей сохранены. Контент, preview-only/noindex и статусы не изменены.


### Диагностика CI и модальность ввода

Провалы browser audit публикуют измеренные details в экранированных GitHub-аннотациях,
не только в ZIP. Это выявило зависимость старого focus-теста от предыдущего ввода:
.focus() после мыши не обязан включать :focus-visible. Стресс-тест теперь начинает
с мыши, проходит Shift+Tab → Tab через настоящий tab order, проверяет возврат фокуса,
его обводку и нативный ArrowRight. Стили и условия прохождения не ослаблены.
