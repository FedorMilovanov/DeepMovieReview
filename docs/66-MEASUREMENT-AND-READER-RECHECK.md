# Повторная проверка измерений и читательских маршрутов

Проверка выполнялась на ветке `arena/f1fa4e24-deepmoviereview` после PR-головы `01d8f12a1d6879e1b30944a1f22a3b24ee06b6ce`. Это локальные изменения, а не утверждение, что публичный сайт уже обновлён. Полный мастер не был доступен для повторного пересчёта хеша; звуковую дорожку не прослушивали. Выборочные кадры и субтитры не равны непрерывному просмотру со звуком.

## Воспроизведённые ошибки

- На синтетических субтитрах `[1,10], [2,3], [4,5], [12,13]` старый код находил ложные промежутки `[3,4]` и `[5,12]` вместо `[10,12]`. Теперь интервалы объединяются по максимальному концу; отдельно проверены вложенные, пересекающиеся, примыкающие, раздельные и последняя вложенная запись. Последняя граница покрытия и хвост считаются от максимального конца.
- В старом JSON поле `meanSecondsBetweenTransitions` называло средним интервалом отношение длины файла к числу обнаружений. Теперь это две величины: `runtimeSecondsPerDetectedTransition` и среднее `meanSecondsBetweenTransitions` по `adjacentTransitionGapCount` промежуткам. Для нуля или одного обнаружения среднее промежутков отсутствует, а не выдумывается.
- На странице счётчик SRT-блоков назывался строками субтитров. Одна запись может занимать несколько строк и не обязательно равна реплике. В таблицах окон считаются **начала** записей, а не все записи, активные внутри окна. Отсутствие субтитров не доказывает тишину или отсутствие речи.
- Опора `truman-ev-boat` указывает 4840 с; в унаследованном журнале перечислены кадры 4830 и 4850 с, а не отдельная проверка 4840 с. Карточка теперь показывает отдельные отметки и ожидающую проверку конкретного момента. `truman-ev-setting-sail` унаследовал ту же основу, но его момент находится вне родительского диапазона. Унаследованные записи не считаются независимыми проверками.
- Две ссылки из статьи на фильм теряли выбранный уровень спойлеров. Обе используют один и тот же helper. Он заменяет старый параметр, сохраняет остальные и ставит query перед fragment; `NONE` удаляет даже повторённые старые значения. Страница `/making` — отдельный маршрут, а не продолжение проекции статьи.

## Предоставленный метаархив, не оригинальный мастер

Из предоставленного `film001-meta.zip` (SHA-256 `70e8bf79657edaf1bdccac0e7a758d25a7ec44d2cca6ab2990e2901312b37396`) извлечены именно те входы, хеши которых записаны в committed dataset:

- `03-subs-en.srt`: SHA-256 `db464c73e14a0d8d363e0d6fa5472e1483ad3d081580a90e9daff726628ef72d`; независимый разбор нашёл **695 блоков, 1181 непустую текстовую строку, 0 пересечений, 0 примыканий**. Число реплик не установлено. Поэтому исправление объединения интервалов **не изменило** полученные из этого SRT промежутки или ранжирование.
- `04-cuts.csv`: SHA-256 `77d91365975e99c89944f5c3f8b7fee9eb85ceb58d1964a6a99b80529ad392b6`; 1019 строк, минимальный записанный score `0.3209`, ниже или равных `0.32` нет. Противоречия порогу в этом CSV не обнаружено. Уязвимость прежнего потребителя — отсутствие проверки — воспроизведена на синтетической строке `0.3199` при пороге `0.32`. Новая проверка учитывает шестизначную печать FFmpeg и последующее округление до четырёх знаков; равный порогу округлённый score сам по себе не доказывает ошибку или исходное значение.
- Длина `6177.792` с / 1019 = `6.06` с на обнаружение; среднее 1018 последовательных промежутков между первым `19.144` и последним `5760.755` с = `5.64` с. Края файла входят в первое отношение, но не во второе. Детектор не является полным монтажным листом; пример пропущенной смены планов описан в `docs/63-FILM-001-CLIP-REVIEW.md`.

До исправления генератор воспроизводил старый committed JSON побайтно. После исправления JSON заново сформирован **генератором** из тех же хешированных SRT/CSV и проверен побайтным сравнением с его stdout; вручную цифры не редактировались. Условия, таблицы интервалов и окна для этого набора не изменились; изменены описание метода и схема двух статистик.

## Состояние проверок и границы

- Последний удалённый CI на **предыдущем** SHA `01d8f12a1d6879e1b30944a1f22a3b24ee06b6ce`: `app-shell` упал на Firefox `image.decode(): Invalid image request`; native iOS Safari также упал на `execute/sync` после команды свайпа. Chromium/Firefox/WebKit rendered contrast и Windows/macOS Actual AT прошли. Это не результат для последующих локальных изменений. Причина обоих падений не установлена.
- В SHA-проверенных данных iOS Simulator для этого прогона касание переключило статью FULL → NONE (11 секций → 1, верный URL и активный NONE). Следующий свайп и закреплённая панель после прокрутки не подтверждены: запрос `execute/sync` истёк. Simulator не равен физическому iPhone или проверке VoiceOver.
- Reader-проверки дополнены реальными переходами по двум ссылкам для всех пяти уровней в Chromium с работающими скриптами и без JavaScript. Локальный тест доступности `:has()` fallback — симуляция условий CSS, а не проверка старого браузера. Перечисление якорей в серверной разметке само по себе не доказывает скролл или iOS-поведение.
- Опубликованная ветвь главной строится через `FilmHero`, маршруты, `LensStage` и `DataSections`; fixture/preview — отдельные ветви. Футер считает опубликованные записи реестра и не объявляет состояние деплоя по догадке.
- Кадры остаются включены согласно редакционному решению, но `DMR_FILM_STILLS_ENABLED=false` перекрывает даже включённый preview. Флаг должен быть задан **и при сборке, и при запуске**: главная статически предрендерена. В отдельной production-сборке с preview включённым и кадрами выключенными приложение отдало fixture с 200, прямой URL кадра с 404, а главная и FULL-статья не содержали `/film-stills/`; Chromium проверил 320/390/1440 с JS и без него. Такая блокировка не удаляет кадры из истории публичного Git.
- Разрешение на воспроизведение кадров не установлено метаданными, хешем, credit или выборочной проверкой; редакционно-правовая проверка остаётся отдельной задачей. Физический iPhone/VoiceOver, полный мастер и звук не проверены; сравнительный обзор «50 сайтов» не проводился.
