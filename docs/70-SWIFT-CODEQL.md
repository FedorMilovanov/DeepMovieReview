# Swift / CodeQL: нативный тестовый сценарий

Единственный Swift-код в репозитории — `scripts/ios-native-ui/Tests/NativeGestureTests.swift`,
тестовый драйвер Mobile Safari, а не часть приложения. После squash merge PR #129
автоматическая конфигурация CodeQL обнаружила Swift, но отдельный её
[autobuild на `ef47abe`](https://github.com/FedorMilovanov/DeepMovieReview/actions/runs/41352142172/job/124984455518)
завершился ошибкой; штатная проверка JS/Python/Actions при этом прошла. Факт
сбоя не означает ни обнаруженной уязвимости, ни успешного анализа Swift.

Автосборщик CodeQL пропускает Xcode UI/unit-test targets. `Package.swift` в
`ios-native-ui` предоставляет для анализа обычный macOS library target с тем
же единственным файлом `Tests/NativeGestureTests.swift`, без копии исходника и
без зависимостей. Пакет не поставляется пользователю и не запускает XCTest:
реальный iOS тест по-прежнему собирается `NativeGesture.xcodeproj` и проходит
отдельный Simulator-gate. Это путь к анализу настоящего исходника, а не заглушка
вместо проверки.

CI отдельно запускает CodeQL Swift с autobuild и security-extended rules, сохраняет
оригинальный SARIF и проверяет отсутствие результатов и ошибок/предупреждений
экстрактора. Он также требует diagnostic `swift/diagnostics/successfully-extracted-files`
для каждого отслеживаемого Swift-файла, включая настоящий XCTest: успешная
сборка сама по себе не доказывает покрытие. На PR явно включён сбор file-coverage
diagnostics; диагностические ошибки и ненулевой счётчик unresolved AST отклоняются,
даже если файл одновременно указан как извлечённый.

На `498b45a` автобилд прошёл, но [загрузка advanced SARIF](https://github.com/FedorMilovanov/DeepMovieReview/actions/runs/41353059862/job/124987195293)
завершилась отказом GitHub: advanced CodeQL несовместим с включённым default setup.
На `881efd6` оригинальный SARIF удалось восстановить и проверить: извлечены оба
отслеживаемых Swift-файла, уведомлений warning/error и результатов нет; 25 security
rules находятся в `tool.extensions`, а не в пустом `driver.rules`. Однако отчёт
имел `incrementalMode: diff-informed`, поэтому ноль результатов **не** доказывает
чистоту всего файла. Следующие SHA отключают diff-informed/overlay и отклоняют
отчёт с их признаками; результат полного анализа `c871458` описан ниже.
Поэтому дополнительный job **не загружает** SARIF в Security tab: он сохраняет
оригинал как артефакт, публикует его через проверяемый Checks API и не проходит
при любом найденном результате, ошибке, предупреждении или отсутствии доказательства
извлечения. Успешная транспортировка сама по себе не является результатом анализа.
Это не отключение Swift-проверки и не утверждение о состоянии Security tab.

Дополнительные полные `security-extended` задания для JS/TS, Python и Actions
также отключают diff/overlay и проверяют исходный SARIF: все отслеживаемые
исходники соответствующего языка должны присутствовать в file-coverage diagnostic,
а находки и предупреждения извлечения недопустимы. Оригинальные отчёты доступны
для независимой проверки через ту же схему. Это отдельная проверка текущего
дерева, не замена Security tab, не скан секретов и не доказательство отсутствия
исторических алертов. Default CodeQL продолжает сканировать эти языки обычным
путём.

На `b94c564` и `2b15d9e` дополнительные задания JS/Python/Actions на `main`
действительно проанализировали и проверили SARIF, но попытка автоматически
загрузить их CodeQL databases закончилась `Resource not accessible by integration`.
Зелёный статус job не отменяет эти warning/error annotations. `upload: never`
отключает только отправку SARIF, тогда как отдельная загрузка database по умолчанию
включена на default branch. Для дополнительного job добавлено ограниченное этим
job разрешение `security-events: write` (как у уже работающего Swift job); его
проверка по PR не выполняет default-branch upload. Отдельно нужно подтвердить
на новом SHA `main`, что базы загрузились и warning/error annotations больше нет.
Проверка SARIF и транспорт оригиналов при этом остаются обязательными, default
CodeQL по-прежнему выполняется независимо.

На `30ef2ed` полный SARIF Python (48 security rules, 2 файла) и Actions
(23 правила, 1 workflow) не содержал результатов. Полный JS/TS SARIF показал
три результата в тестовой/диагностической инфраструктуре: путь к запускаемому
bundle-инструменту, проверку синтаксиса observer через `vm.Script` и запись
непроверенного ответа SafariDriver в диагностический JSON. Речь об отдельных
путях, а не о доказанной эксплуатации сайта. Устранение проверяется на новом SHA
без исключения тестовых файлов и без подавления правил: путь привязан к модулю,
синтаксис проверяется без исполнения, из capabilities сохраняются только
валидированные поля идентификации Simulator. Предыдущие результаты не переносятся
на новый SHA.

На `c871458` независимое чтение исходных SARIF подтвердило полный `security-extended`
без diff/overlay и без результатов: JS/TS — 101 security rule, 174 отслеживаемых
файла; Python — 48 правил, 2 файла; Actions — 23 правила, 1 workflow; Swift —
25 правил, 2 файла. Диагностических предупреждений извлечения не было. Это результат
только данного SHA, не инвентарь исторических alerts и не скан секретов.

Отдельно требуется проверить штатный default setup на main; доступный API его
настроек и инвентаря старых alerts отвечает HTTP 403. Новый сценарий должен быть
проверен на точном SHA; до успешного выполнения невозможно утверждать, что Swift
проанализирован или default setup исправлен.
